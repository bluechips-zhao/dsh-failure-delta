# Web 看板与交互规范

目标：用户能直接看到每次检查比上次多了什么、还剩什么，以及哪些变化不能确认。不是另一个原始日志窗口。

## 布局示意

```text
Failure Delta                         [运行列表] [刷新]
会话内数据 · 宿主重启后清空            数据状态：最新/刷新中/过期
当前：tsc #8   基线：#7 [更换]         退出码：1
证据等级：有限观察                     [为什么？]
新增 1 | 持续 2 | 未再观察到 9
⚠ 输出截断，不能据此认定 9 项已经修复
--------------------------------------------------
[新增] [持续] [未再观察到] [未确认测试]
src/a.ts  TS2322  …脱敏短摘录…         [原工具调用]
--------------------------------------------------
健康：1 次记录丢失 · 3 次历史淘汰      [详情]
```

数字为说明示例，不是本项目运行结果。诊断次数与测试用例数分区展示，不能混成修复总数。

## 主要界面

1. 运行列表：runner、开始序号、观测时间、进程结果、记录状态、完整性提示；未知命令显示“未支持的检查”，不显示空绿色卡片。
2. 对比详情：当前/基线身份、等级、原因、分类条目；首轮没有基线时显示单次结果，不造 0→N。
3. 健康详情：队列丢失、淘汰、记录器故障、资源上限、宿主 epoch 变化；不是静默 toast 后消失。

官方候选扩展点为 sidebarRight / sidebarRightTabs 或 ui-slots；D1 必须验证具体插槽、组件契约和会话绑定。客户端必须通过官方 client module 和 Remote 路径，不使用 DOM 注入、私有状态或猜 URL。

## 文案约束

| 状态 | 必须使用的措辞 | 禁止 |
|---|---|---|
| 显式 failed→passed | 本次通过 | 已永久修复 |
| 完整可比诊断缺失 | 本次检查不再出现 | 已证明修复/根因解决 |
| 有限日志缺失 | 未再观察到 | 已解决/通过 |
| 跳过、缺失、歧义用例 | 未确认 | 减少失败就是通过 |
| 条件变化 | 不可比较：范围/配置等变化 | 修复率提升 |
| 退出码 0 | 本次进程退出码为 0 | 全部检查已通过 |
| 原始日志入口 | 原工具调用 | 插件已保存完整日志 |

按类别列出统计单位。有限观察和不可比较不能绿色成功横幅。可用颜色辅助，但必须有图标/文本及可读对比度。reasonCodes 逐条可展开，用明白的中文说明影响。

## 操作边界

- 更换基线：仅限授权会话可见运行，重新执行证据门槛；不能提供“强制认定已修复”。
- 刷新：重新获取插件派生快照，绝不重新执行测试。
- 原工具调用：官方导航可用才启用；不可用则给出可复制调用 ID，不拼 URI。
- 查询工具：由 Agent 按需使用，参数与输出有界；不改变 Web 看板基线偏好。
- v1 无自动修复、一键 shell 重跑、阻塞完成、全文导出或跨会话汇总。

## 加载与恢复

面板打开时授权请求快照。官方订阅能力验证后优先使用；没有可用订阅可采用官方 Remote 有界轮询，默认 5 秒、错误退避至 30 秒，仅面板可见时运行，关闭停止。不能自建未经授权的 HTTP 轮询端点。

刷新期间保留最后快照并明确“过期”；请求失败不能显示空列表代表零失败。收到新 epoch 清空旧视图，说明“宿主重启，观察历史已清空”。revision 回退/跳跃时重新获取完整快照，不在客户端自行补算。

## 可访问性与窄屏

分类标签、基线选择、刷新和原调用入口均可键盘操作；焦点不被后台刷新抢走。aria-live 只汇报重要状态且节流。小屏采用单列、分类标签可横向滚动，长摘录换行。纯文本渲染且保留必要转义，禁止 HTML/Markdown 原样渲染工具输出。
